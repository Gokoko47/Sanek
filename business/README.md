# Pakostnik через Telegram Business

**Запуск на Android без отдельного сервера:** [инструкция Termux](PHONE.md). Мастер `python -m business.phone setup`, запуск — `python -m business.phone run`. Оплата OpenAI API остаётся отдельной.

Серверный бот отвечает **через ваш Business-аккаунт**, используя официальный Bot API и `business_connection_id`. Он не входит в пользовательскую сессию и не требует личных `api_id` / `api_hash`. Собственный Android-клиент для этого варианта не нужен.

Состояние: код подготовлен, автоматические проверки с подменой Telegram и ИИ пройдены. Реальное подключение, доставка сообщений и запуск 24/7 пока не проверены: токены и хостинг пользователя ещё не настроены. Никаких настоящих сообщений из рабочей среды не отправлялось.

## 1. Создайте бота

1. В официальном `@BotFather` отправьте `/newbot`, задайте имя и username.
2. В `/mybots` выберите бота → **Bot Settings → Business Mode** → включите режим Business. Названия кнопок могут отличаться в локализации.
3. Сохраните выданный токен только в переменной сервера `TELEGRAM_BOT_TOKEN`. Не публикуйте его в исходниках, GitHub или переписках.

## 2. Запустите режим настройки

Нужен постоянно работающий сервер/worker с Python 3.11+ и исходящим HTTPS-доступом к `api.telegram.org` и `api.openai.com`. Домен, входящий порт и webhook не нужны: бот получает обновления через long polling.

На сервере в каталоге этого репозитория задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_ID=0` в настройках окружения хостинга. Запустите:

```bash
python3 -m business.bot
```

В Telegram откройте своего бота и отправьте `/id`. Он покажет **ваш числовой Telegram user ID**. Запишите его в `TELEGRAM_OWNER_ID` в окружении сервера. В режиме ID=0 бот не отвечает от Business-аккаунта и не обращается к ИИ.

## 3. Настройте ИИ и постоянный запуск

Добавьте в окружение:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен вашего бота от BotFather |
| `TELEGRAM_OWNER_ID` | Ваш числовой ID, полученный командой `/id` |
| `OPENAI_API_KEY` | Ключ OpenAI API; подписка ChatGPT сама по себе не заменяет его |
| `OPENAI_MODEL` | По умолчанию `gpt-4.1-mini` |
| `REPLY_STYLE` | По умолчанию: коротко, разговорно, на ты, с маленькой буквы, без канцелярита и лишних эмодзи |
| `STATE_PATH` | Постоянный путь SQLite, по умолчанию `data/business.sqlite3` |

Остальные параметры есть в `.env.example`. Файл `.env` сам по себе скриптом не читается: используйте переменные хостинга или `EnvironmentFile` в systemd. Токены хранятся в окружении сервера, не в SQLite и не в логах.

Перезапустите сервис. Для VPS есть шаблон `pakostnik-business.service`: укажите существующего непривилегированного пользователя, путь к репозиторию и закрытый файл окружения. На managed hosting создайте **Background Worker**, а не HTTP Web Service: команда старта `python -m business.bot`, рабочий каталог — корень репозитория. `business/Procfile` содержит ту же команду. Для SQLite подключите постоянный диск и задайте соответствующий `STATE_PATH`.

Нужен один экземпляр процесса на токен и один общий файл состояния. Второй polling-процесс создаёт конфликт 409. Если у бота уже есть webhook, сервис откажется запускаться, не удаляя существующую конфигурацию. Сначала осознанно отключите прежнюю интеграцию.

GitHub Actions выполняет только тесты. Он не является круглосуточным хостингом этого бота. Сервис остановится при остановке/засыпании выбранного сервера; для непрерывной работы нужен соответствующий хостинг. Использование ИИ оплачивается по правилам провайдера.

## 4. Подключите к аккаунту

В своём Telegram откройте **Настройки → Telegram Business → Чат-боты**:

1. Укажите username вашего бота.
2. Выберите переписки, в которых он должен работать: все подходящие личные или выбранные.
3. Разрешите боту отправлять ответы и сохраните подключение.
4. Попросите другой аккаунт прислать **новое обычное текстовое сообщение после запуска сервиса**.

Бот принимает Business-подключения только вашего `TELEGRAM_OWNER_ID`. Другая учётная запись не сможет использовать ваш экземпляр даже при подключении того же публичного бота. Перед отправкой проверяется актуальное подключение и `rights.can_reply`. Telegram разрешает такие ответы в личных чатах с входящими за последние 24 часа; сам сервис дополнительно ограничивает обработку свежими сообщениями, чтобы не отвечать массово на старую очередь.

## Управление

Команды отправляются **в личный чат с ботом**, а не в переписку с собеседником:

- `/menu` — отдельное меню с кнопками: режимы чатов, стиль, память, задержка и распознавание.
- `/chats` — список переписок с переключением между ручным режимом, помощником с подтверждением и автопилотом.
- `/status` — состояние автопилота.
- `/pause` — остановить автоответы и отменить ожидающие результаты.
- `/resume` — возобновить автоответы в разрешённых переписках.
- `/style коротко, на ты, с маленькой буквы, без лишних эмодзи` — изменить стиль, до 500 символов.
- `/example как дела? => да норм, ты как` — добавить образец вашего обычного ответа.
- `/examples` — посмотреть добавленные образцы.
- `/clearstyle` — удалить образцы и вернуть стиль из `REPLY_STYLE` сервера.
- `/resumechat 123456789` — снять локальную паузу/остановку с указанного чата.
- `/memory` — настройки короткого контекста; `/clearcontext` — очистить его во всех чатах.
- `/voice` — включение распознавания голосовых и кружков; по умолчанию выключено.
- `/delay 6` — объединять серию сообщений после паузы в 6 секунд (диапазон 0–30).
- `/id` — показать собственный Telegram ID.

Команды управления доступны только владельцу из `TELEGRAM_OWNER_ID`; `/id` показывает каждому пользователю только его собственный ID.

Если вы отвечаете вручную в Business-переписке, ожидающий ответ ИИ отменяется и в этом чате включается пауза на 30 минут. Снять её раньше можно `/resumechat`. Собственные ответы бота не вызывают такую паузу. При включённой памяти безопасный текст ручных ответов и ответы ИИ входят в короткий контекст следующей генерации; они не становятся образцами стиля автоматически.

В первом автоматическом ответе присутствует уведомление об ИИ-помощнике. Отдельного префикса `[ИИ]` у каждого сообщения нет. Подтверждение собеседника `/ai-ok` не требуется. Собеседник может написать `/stop` — новые автоответы в этой переписке прекратятся до явного `/resumechat` владельца.

## Отвечать в вашей манере

После запуска сервера отправьте команды **в личный чат с вашим ботом** со своего аккаунта:

```text
/style коротко, разговорно, на ты, чаще с маленькой буквы, без канцелярита и лишних эмодзи
/example привет, как ты? => здарова, да норм, ты как
/example что делаешь? => пока занят, попозже напишу
/example спасибо! => да без проблем
```

Это синтетические примеры формата. Для сходства добавьте 3–8 собственных обычных ответов с разными настроениями. Модель учитывает длину фраз, лексику, регистр, пунктуацию, юмор и эмодзи. Образцы используются как ориентиры стиля, а не как достоверные факты о текущих делах или планах владельца. Сходство нужно оценить в тестовом чате; точное воспроизведение человека не гарантируется.

Хранятся до восьми последних разных пар, до 500 символов в каждой части. После `/example` ожидающие старые ответы отменяются, чтобы новый стиль применялся к следующим сообщениям. Просмотр `/examples` и редактирование доступны только владельцу. Стиль и образцы сохраняются в закрытом файле состояния на сервере, а не в публичном репозитории. Они передаются вашему ИИ-провайдеру при генерации — не добавляйте пароли, коды и лишние личные сведения. Фильтр отклоняет распознанные чувствительные примеры.

`/clearstyle` удаляет образцы из активного состояния сервиса и возвращает серверный `REPLY_STYLE`. Эта команда не отменяет уже отправленные провайдеру запросы и не удаляет резервные копии хостинга. Автоматического чтения всей истории аккаунта или скрытого накопления ваших ручных ответов нет: примеры выбираете вы.

Это персонализация запросов, а не отдельное обучение/дообучение модели. Уведомление об ИИ-помощнике в первом автоответе и ограничения на важные решения сохраняются; префикса `[ИИ]` у каждого ответа по-прежнему нет.

## Режимы и качество ответов

Откройте `/menu` → «Чаты» и выберите переписку. «Автопилот» отвечает самостоятельно, «Помощник» присылает предложение в личку владельцу, «Ручной» отключает ИИ в этой переписке. Общая пауза имеет приоритет над режимами. Локальная остановка `/stop` и пауза после ручного вмешательства снимаются отдельно.

В режиме помощника доступны «Отправить», «Исправить» и «Отклонить». Исправление сначала показывается для проверки. Кнопка «Отправить и запомнить мой вариант» сохраняет явно исправленный владельцем ответ как образец стиля, если обе части до 500 символов. Непроверенный ответ модели автоматически образцом не становится. Предложения действуют не дольше 3 минут от входящего сообщения; новые сообщения, правки, удаления или изменение настроек делают старое подтверждение недействительным. Повторные нажатия не создают повторную попытку доставки.

По умолчанию сообщения объединяются после 6 секунд тишины; непрерывная серия обрабатывается примерно через 20 секунд (при настройке задержки больше 20 секунд — через эту задержку). Предел одной серии — 12 сообщений, 4000 символов и 3 записи. Это позволяет отвечать на законченную мысль. Избыточная серия передаётся на ручной разбор.

Контекст включён по умолчанию: последние 12 сообщений, до 6000 символов на чат и до 24 часов, не более 500 сообщений во всех чатах. Одно сохранённое сообщение сокращается до 2000 символов. В него входят только новые сообщения, полученные сервисом, безопасные ручные ответы и подтверждённые ответы бота. Полная история Telegram не загружается. В `/memory` память можно отключить и очистить; доступна очистка конкретной переписки. При редактировании/удалении сообщения короткая память этого чата полностью сбрасывается, чтобы не сохранять его пересказ в старом ответе. Это не функция просмотра удалённых сообщений.

В `/voice` можно явно включить распознавание **новых голосовых и видеокружков**. Записи до 5 минут и 10 МБ загружаются из Telegram и отправляются OpenAI для транскрипции; бот отвечает текстом. Файл обрабатывается в оперативной памяти, отдельный медиаархив не создаётся. Распознавание тарифицируется отдельно от генерации. Видео кружка визуально не анализируется. Фото, документы, обычные видео и прочие вложения требуют ручного просмотра.

Для важных/чувствительных вопросов, неподдерживаемых вложений и ошибок сервиса включается удержание чата: новые автоответы прекращаются, владелец получает уведомление с кнопкой управления. Вручную ответьте в Telegram или явно возобновите чат. Полной гарантии распознавания важных вопросов нет. Пользовательское сообщение и короткий контекст передаются модели как недоверенные данные; личные факты и обязательства выдумывать запрещено.

## Ограничения и данные

- Только выбранные в Telegram личные Business-переписки, с действующим правом ответа. Ограничение Telegram — входящие за последние 24 часа; этот сервис дополнительно обрабатывает только свежие сообщения, по умолчанию до 180 секунд и не старше запуска.
- По умолчанию: 60 попыток доставки и 90 запросов ИИ в час на весь сервис; распознавание тоже расходует лимит запросов. Это предел количества, не денежный бюджет. Ограничение расходов дополнительно задаётся у провайдера. Между отправками в одном чате — 5 секунд. Пропущенные по лимиту сообщения не копятся для поздней отправки.
- Повторы обновлений отсеиваются SQLite. После неоднозначного сетевого сбоя отправка не повторяется автоматически: Telegram не предоставляет ключ идемпотентности `sendMessage`. Возможны пропуски; проверьте чат перед ручным повтором. Уже отправленный в сеть запрос невозможно отозвать.
- Сетевые сбои запуска и polling обрабатываются с увеличивающейся паузой. Неверный токен, второй polling-процесс и существующий webhook требуют устранения причины. Очередь генераций ограничена; после перезапуска ожидающие ответы не восстанавливаются.
- SQLite содержит ID, счётчики, настройки, явно выбранные образцы, ограниченный текстовый контекст и краткоживущие предложения ответов (до 100, примерно на 3 минуты). Очистка контекста удаляет и локальные предложения. Файл имеет права 600, каталог — 700; это не отдельное шифрованное хранилище. Устаревшие записи удаляются при работе сервиса, после его остановки — при следующем запуске.
- Предложения и уведомления, уже отправленные владельцу в Telegram, остаются сообщениями Telegram. Очистка SQLite не удаляет их из лички и не отзывает данные у провайдера или из резервных копий. Журналы приложения не содержат текста переписок и токенов.
- Business-бот не меняет интерфейс официального Telegram. Консольная тема, запись/отправка медиа и сохранение удалённых сообщений с крестиком относятся к отдельному Android-клиенту. Этот этап — автоответы через Business на телефоне.

python3 -m unittest discover -s business/tests -v

127 проверок используют подмены Telegram/ИИ, не требуют токенов и не отправляют сообщений. Отдельный workflow — `.github/workflows/business.yml`.

Ссылки на API: [BusinessConnection](https://core.telegram.org/bots/api#businessconnection), [BusinessBotRights](https://core.telegram.org/bots/api#businessbotrights), [sendMessage](https://core.telegram.org/bots/api#sendmessage). Структура `rights.can_reply` и правило 24 часов сверены с актуальным исходником SDK `python-telegram-bot` (`src/telegram/_business.py`); устаревшее поле `BusinessConnection.can_reply` не используется.

## Вариант размещения: Railway из этого репозитория

Подготовлены `railway.toml` и `business/Dockerfile`. Это конфигурация, а не уже созданный/оплаченный сервер. Актуальные условия и стоимость проверьте в Railway до включения постоянной работы.

1. Войдите на [railway.com](https://railway.com) через GitHub → создайте проект из GitHub-репозитория **Gokoko47/Sanek**. При запросе доступа разрешите Railway доступ к этому репозиторию. Рабочий каталог оставьте корнем репозитория: конфигурация сама выберет Dockerfile Business-бота.
2. Добавьте к сервису постоянный **Volume** с точкой монтирования `/data`. Оставьте **одну реплику** и выключите режим сна/Serverless, если он включён: polling-бот должен работать постоянно. Настройка публичного HTTP-домена не нужна.
3. В **Variables** добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_ID=0`. `STATE_PATH` укажите `/data/business.sqlite3`. Запустите Deploy. Без токена начальный автозапуск может завершиться ошибкой — после сохранения Variables выполните Deploy заново.
4. В Telegram отправьте своему боту `/id`, скопируйте показанный числовой ID. В Variables замените `TELEGRAM_OWNER_ID` на этот ID, добавьте `OPENAI_API_KEY` и, при желании, `OPENAI_MODEL` / `REPLY_STYLE`. Примените изменения и дождитесь запуска сервиса.
5. Подключите бота в **Telegram Business → Чат-боты**, выберите нужные переписки, разрешите ответы. Для проверки отправьте новое сообщение с другого аккаунта.

Настройки переменных находятся на стороне Railway, а не в репозитории. Логи показывают состояние сервиса и коды ошибок без токенов и содержимого сообщений. При сбое сначала проверьте токен, Business Mode в BotFather, собственный ID, право ответа, ключ ИИ и наличие постоянного диска. Конфигурация контейнера и запуск на Railway ещё требуют проверки после настройки пользовательского аккаунта и переменных.
