# Pakostnik через Telegram Business

Серверный бот отвечает **через ваш Business-аккаунт**, используя официальный Bot API и `business_connection_id`. Он не входит в пользовательскую сессию и не требует личных `api_id` / `api_hash`. Собственный Android-клиент для этого варианта не нужен.

Состояние: код подготовлен, автоматические проверки с подменой Telegram и ИИ пройдены. Реальное подключение, доставка сообщений и запуск 24/7 пока не проверены: токены и хостинг пользователя ещё не настроены. Никаких настоящих сообщений из рабочей среды не отправлялось.

## 1. Создайте бота

1. В официальном `@BotFather` отправьте `/newbot`, задайте имя и username.
2. В `/mybots` выберите бота → **Bot Settings → Business Mode** → включите режим Business. Названия кнопок могут отличаться в локализации.
3. Сохраните выданный токен только в переменной сервера `TELEGRAM_BOT_TOKEN`. Не публикуйте его в исходниках, GitHub или переписках.

## 2. Запустите режим настройки

Нужен постоянно работающий сервер/worker с Python 3.11+ и исходящим HTTPS-доступом к `api.telegram.org` и `api.openai.com`. Домен, входящий порт и webhook не нужны: бот получает обновления через long polling.

На сервере в каталоге этого репозитория задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_ID=0` в настройках окружения хостинга. Запустите:

```bash
python3 -m business.bot
```

В Telegram откройте своего бота и отправьте `/id`. Он покажет **ваш числовой Telegram user ID**. Запишите его в `TELEGRAM_OWNER_ID` в окружении сервера. В режиме ID=0 бот не отвечает от Business-аккаунта и не обращается к ИИ.

## 3. Настройте ИИ и постоянный запуск

Добавьте в окружение:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен вашего бота от BotFather |
| `TELEGRAM_OWNER_ID` | Ваш числовой ID, полученный командой `/id` |
| `OPENAI_API_KEY` | Ключ OpenAI API; подписка ChatGPT сама по себе не заменяет его |
| `OPENAI_MODEL` | По умолчанию `gpt-4.1-mini` |
| `REPLY_STYLE` | Например «Дружелюбно, кратко, с лёгким юмором.» |
| `STATE_PATH` | Постоянный путь SQLite, по умолчанию `data/business.sqlite3` |

Остальные параметры есть в `.env.example`. Файл `.env` сам по себе скриптом не читается: используйте переменные хостинга или `EnvironmentFile` в systemd. Токены хранятся в окружении сервера, не в SQLite и не в логах.

Перезапустите сервис. Для VPS есть шаблон `pakostnik-business.service`: укажите существующего непривилегированного пользователя, путь к репозиторию и закрытый файл окружения. На managed hosting создайте **Background Worker**, а не HTTP Web Service: команда старта `python -m business.bot`, рабочий каталог — корень репозитория. `business/Procfile` содержит ту же команду. Для SQLite подключите постоянный диск и задайте соответствующий `STATE_PATH`.

Нужен один экземпляр процесса на токен и один общий файл состояния. Второй polling-процесс создаёт конфликт 409. Если у бота уже есть webhook, сервис откажется запускаться, не удаляя существующую конфигурацию. Сначала осознанно отключите прежнюю интеграцию.

GitHub Actions выполняет только тесты. Он не является круглосуточным хостингом этого бота. Сервис остановится при остановке/засыпании выбранного сервера; для непрерывной работы нужен соответствующий хостинг. Использование ИИ оплачивается по правилам провайдера.

## 4. Подключите к аккаунту

В своём Telegram откройте **Настройки → Telegram Business → Чат-боты**:

1. Укажите username вашего бота.
2. Выберите переписки, в которых он должен работать: все подходящие личные или выбранные.
3. Разрешите боту отправлять ответы и сохраните подключение.
4. Попросите другой аккаунт прислать **новое обычное текстовое сообщение после запуска сервиса**.

Бот принимает Business-подключения только вашего `TELEGRAM_OWNER_ID`. Другая учётная запись не сможет использовать ваш экземпляр даже при подключении того же публичного бота. Перед отправкой проверяется актуальное подключение и `rights.can_reply`. Telegram разрешает такие ответы в личных чатах с входящими за последние 24 часа; сам сервис дополнительно ограничивает обработку свежими сообщениями, чтобы не отвечать массово на старую очередь.

## Управление

Команды отправляются **в личный чат с ботом**, а не в переписку с собеседником:

- `/status` — состояние автопилота.
- `/pause` — остановить автоответы и отменить ожидающие результаты.
- `/resume` — возобновить автоответы в разрешённых переписках.
- `/style Дружелюбно, очень коротко` — изменить стиль, до 500 символов.
- `/resumechat 123456789` — снять локальную паузу/остановку с указанного чата.
- `/id` — показать собственный Telegram ID.

Команды управления доступны только владельцу из `TELEGRAM_OWNER_ID`; `/id` показывает каждому пользователю только его собственный ID.

Если вы отвечаете вручную в Business-переписке, ожидающий ответ ИИ отменяется и в этом чате включается пауза на 30 минут. Снять её раньше можно `/resumechat`. Собственные ответы бота не вызывают такую паузу и не передаются обратно модели.

В первом автоматическом ответе присутствует уведомление об ИИ-помощнике. Отдельного префикса `[ИИ]` у каждого сообщения нет. Подтверждение собеседника `/ai-ok` не требуется. Собеседник может написать `/stop` — новые автоответы в этой переписке прекратятся до явного `/resumechat` владельца.

## Реальные границы первой версии

- Обрабатывается новый обычный текст из разрешённых личных Business-переписок. История аккаунта не выгружается; модели передаются одно входящее сообщение и стиль владельца.
- Голосовые, кружки, медиа и групповые чаты эта серверная версия пока не обрабатывает. Ваш обычный Telegram продолжает работать штатно.
- Важные/чувствительные сообщения и ответы фильтруются до отправки; модель должна возвращать `review` при неопределённости. Такие вопросы нужно проверять и отвечать вручную. Полной гарантии распознавания важных вопросов нет, отдельные уведомления владельцу о каждом пропуске пока не реализованы.
- По умолчанию: максимум 60 попыток автоответа в час и пауза 5 секунд между ответами в одном чате. Сообщения, пропущенные по лимиту, не копятся для поздней отправки.
- Старые обновления до текущего запуска не получают автоматических ответов. После перезапуска ранее ожидавшее сообщение может потребовать ручного ответа.
- Повторы обновлений отсеиваются в SQLite; после сетевой ошибки отправка не повторяется автоматически. Bot API не даёт ключ идемпотентности для `sendMessage`, поэтому нельзя обещать одновременно отсутствие пропусков и строго единственную доставку при любом сетевом сбое.
- Новое сообщение, ручное вмешательство, редактирование/удаление исходного, пауза или отзыв прав отменяют ожидающий результат. Уже отправленный в сеть запрос невозможно отозвать задним числом.
- В SQLite хранятся ID, счётчики и параметры управления, но не тексты переписок. Журналы не содержат сообщений или токенов. ИИ-провайдер обрабатывает переданный текст по своим условиям.
- Business-бот не меняет интерфейс официального Telegram. Консольная тема и оставление удалённых сообщений с крестиком относятся к отдельному Android-форку, а не к этой интеграции.

## Проверки

```bash
python3 -m unittest discover -s business/tests -v
```

Проверки используют подмены Telegram/ИИ, не требуют токенов и не отправляют сообщений. Отдельный workflow — `.github/workflows/business.yml`.

Ссылки на API: [BusinessConnection](https://core.telegram.org/bots/api#businessconnection), [BusinessBotRights](https://core.telegram.org/bots/api#businessbotrights), [sendMessage](https://core.telegram.org/bots/api#sendmessage). Структура `rights.can_reply` и правило 24 часов сверены с актуальным исходником SDK `python-telegram-bot` (`src/telegram/_business.py`); устаревшее поле `BusinessConnection.can_reply` не используется.
