# Pakostnik AI — форк Telegram для Android

Это проект **модификации официального Telegram Android**, а не отдельный бот и не макет интерфейса. Обычные сообщения, контакты, история, медиа и вход в аккаунт предоставляет исходный Telegram. Pakostnik добавляет отдельный пункт Pakostnik AI в главном меню и подключает автопилот к получению и отправке сообщений.

**Состояние:** первая реализация для проверки. Готового проверенного APK в архиве нет. 16 тестов сервера, тест фильтра удаления и Java-тест 12 примеров текстового фильтра и отдельная компиляция добавленных Java-классов пройдены. Полная сборка приложения и работа на телефоне ещё не проверены: загрузка нативной зависимости libyuv в рабочей среде заблокирована HTTP 403. GitHub Actions подготовлен, но пока не запускался в вашем репозитории.

## Что находится в архиве

- `bootstrap.sh` скачивает официальный Telegram и все его подмодули на закреплённой версии.
- `apply.py` проверяет версию и вносит изменения в исходники Telegram.
- `overlay/` содержит Java-код автопилота, экран настроек, зашифрованное хранилище токена и собственную иконку.
- `server/` — небольшой сервер доступа к ИИ. Ключ провайдера остаётся на сервере.
- `.github/workflows/android.yml` собирает debug APK в GitHub Actions.
- `tests/` — автоматические проверки сервера.
- `UPSTREAM.txt`, `LICENSE` — источник, закреплённая версия и лицензия.

Большие исходники Telegram не дублируются в ZIP: сборка скачивает их автоматически с GitHub. После `bootstrap.sh` каталог `Telegram/` содержит полноценные изменённые исходники приложения.

## Сборка с телефона через GitHub

1. Создайте приватный репозиторий `pakostnik-ai`.
2. Распакуйте ZIP и загрузите **содержимое** папки `pakostnik-ai` в корень репозитория, включая `.github`. Структура каталогов должна сохраниться. Для массовой загрузки папок можно использовать веб-версию GitHub в режиме компьютера или Git-клиент на телефоне.
3. Откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте:
   - `TG_API_ID`: ваш личный `api_id` с https://my.telegram.org.
   - `TG_API_HASH`: ваш личный `api_hash` оттуда же.
4. Откройте **Actions → Pakostnik Android APK → Run workflow**.
5. После успешной сборки скачайте `pakostnik-ai-debug-apk` из Artifacts. Установите APK из этого архива.

Сборка тяжёлая: потребуются загрузка нативных исходников, Android SDK и NDK. При неудаче нужен журнал конкретного шага. Workflow не обходит сетевые блокировки и не гарантирует успешную сборку без первой проверки.

Имя приложения — Pakostnik AI, application ID — `ai.pakostnik.client.web`. Оно устанавливается отдельно от официального Telegram. Для входа используется штатная авторизация Telegram, включая код и пароль 2FA. API-ключи нужны для сборки; отправлять их в чат не требуется. Использовать `api_id` Telegram вместо собственных проект не позволяет.

Debug-сборка по умолчанию использует тестовый keystore из открытого upstream. Она предназначена для личного тестирования. Для собственного постоянного ключа создайте keystore с alias `androidkey`, store/key password `android`, сохраните его Base64 в repository secret `SIGNING_KEYSTORE_BASE64`. Сохраните оригинал ключа: без него нельзя обновлять установленное приложение с той же подписью. Для публичного релиза настройте отдельную release-подпись и сборку.

Firebase в upstream содержит демонстрационную конфигурацию. Переименование пакета обеспечивает соответствие при сборке, но **не настраивает собственные push-уведомления**. До отдельной настройки Firebase не рассчитывайте на push как на гарантию фонового автопилота. Включённый Telegram и его штатное соединение нужны для получения обновлений.

## Сервер ИИ

Нужен небольшой постоянно работающий сервер с Python 3.10+, доменом и HTTPS. Аккаунт/сервер не создаются автоматически и в архив не включены.

На сервере задайте переменные окружения:

```bash
export OPENAI_API_KEY='ваш-ключ-провайдера'
export PAKOSTNIK_TOKEN='длинный-случайный-токен-не-короче-32-символов'
export OPENAI_MODEL='gpt-4.1-mini'
python3 server/server.py
```

Случайный токен можно получить командой `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`. Секреты храните на сервере, не в Git. Файл `.env.example` — пример; сам сервер `.env` автоматически не читает.

Процесс слушает только `127.0.0.1:8080`. Настройте HTTPS reverse proxy, например Caddy по образцу `server/Caddyfile`, заменив домен на свой. В приложении укажите `https://ваш-домен/reply` и тот же `PAKOSTNIK_TOKEN`. Для постоянной работы настройте запуск через systemd или менеджер процессов своего хостинга.

Сервер использует OpenAI-совместимый формат ответа через официальный OpenAI API. Использование модели оплачивается отдельно. Автотесты подменяют провайдера и не тратят средства.

Не включайте логирование тела запросов в reverse proxy. Сервер не хранит историю и не пишет сообщения в свои журналы; запросы всё равно обрабатываются вашим хостингом и ИИ-провайдером по их условиям. Для автоответа в ИИ передаётся **одно новое текстовое сообщение и настройка стиля**, без ID чата, имени и полной истории. Аудио и видеокружки передаются отдельно только по явному нажатию «Расшифровать».

## Включение автопилота

1. Войдите в Telegram внутри Pakostnik AI.
2. В списке чатов откройте главное меню → **Pakostnik AI**.
3. Сохраните HTTPS URL сервера, токен и стиль: например «Дружелюбно, коротко, с лёгким юмором».
4. Нажмите **Включить ИИ для этого аккаунта** и подтвердите передачу сообщений настроенному сервису.
5. Нажмите **Выбрать чат для настройки**, выберите человека, затем режим **Помощник** или **Автопилот**.
6. Режим включается сразу. Приложение отправит собеседнику уведомление об использовании ИИ; ответ или подтверждение от него не требуются.
7. Новые сообщения после включения режима смогут получать ответы без добавляемого приложением префикса с вашего аккаунта.

**Помощник:** ИИ готовит ответ. Откройте главное меню → Pakostnik AI → выберите чат → «Показать предложенный ответ» → проверьте → «Отправить». Предложение хранится в памяти до двух минут и отменяется при новом входящем или ручной отправке. Это первая версия; отдельной вкладки готовых предложений пока нет.

**Автопилот:** допустимый ответ передаётся штатному механизму отправки Telegram самостоятельно. Ошибки доставки остаются видны в обычном интерфейсе Telegram. Статус «передан на отправку» не означает подтверждённую доставку.

**Ручной:** переписка работает как обычный Telegram.

Остановка: «ОСТАНОВИТЬ ИИ ВО ВСЕХ АККАУНТАХ» на экране Pakostnik AI; либо «Ручной» в конкретном чате. Собеседник может отправить `/stop`. Настройки отдельных аккаунтов разделены. После перезапуска процесса, выхода из аккаунта или изменения подключения ИИ выключается. Для возобновления нужно включить его и выбрать режим нужного чата заново.

## Ограничения автопилота

- Только личные чаты с людьми. Исключены боты, поддержка, сервисный аккаунт, «Избранное», группы, каналы, секретные чаты и чаты с платными сообщениями.
- Только новые текстовые сообщения не старше двух минут. Старые сообщения после восстановления соединения не получают массовых автоответов.
- Повторные обновления отсеиваются по ID сообщения. Ответ на устаревшее сообщение отменяется при новом входящем, ручной отправке, изменении режима или остановке ИИ.
- Максимум 10 автоответов в час на аккаунт и один в минуту на переписку. Пропущенные по лимиту сообщения не копятся для поздней отправки.
- Пароли, коды и ряд финансовых, юридических и других чувствительных тем блокируются текстовым фильтром. Модель дополнительно должна возвращать `review` для важных или неоднозначных вопросов. Автоматической гарантии распознавания всех важных вопросов нет.
- При ошибке сервера, тайм-ауте или сомнительном ответе автоотправки нет; ответьте вручную. Сейчас такие случаи отражаются в статусе экрана ИИ, без отдельного уведомления.
- Остановка отменяет будущие отправки и ещё не начатые запросы. Уже переданный провайдеру запрос нельзя «забрать обратно».
- Фоновая работа наследует ограничения Android и исходного Telegram. После принудительной остановки, выгрузки процесса или при недоступной сети автопилот не работает. Отдельный постоянно работающий сервис автопилота не реализован.

## Локальная сборка

Нужны Git, Python 3, JDK 21, Android SDK 36, build-tools 36.0.0, NDK 27.2.12479018 и CMake 3.22.1.

```bash
bash bootstrap.sh
export TG_API_ID='ваш_api_id'
export TG_API_HASH='ваш_api_hash'
cd Telegram
# Укажите sdk.dir в local.properties, если SDK не найден по ANDROID_HOME.
bash gradlew :TMessagesProj_AppStandalone:assembleAfatDebug --no-daemon --max-workers=2
```

`apply.py` применим только к закреплённой версии и чистому checkout. Если работа прервётся, создайте новый рабочий каталог; скрипт не удаляет существующие исходники.

Проверки сервера: `python3 -m unittest discover -s tests -v`.

## Лицензия и выпуск

Код основан на официальном Telegram Android, лицензированном под GPL. При распространении изменённого приложения соблюдайте лицензию и предоставляйте соответствующий исходный код: закреплённую базу, подмодули, изменения и инструкции сборки. `LICENSE` включён в проект. Используйте собственные идентификаторы API, имя, иконку и необходимые сервисные настройки. Проект не является официальным Telegram.

Перед публичным выпуском отдельно проверьте актуальные условия Telegram API и ИИ-провайдера, включая использование сообщений для ИИ. Уведомление собеседника само по себе не подтверждает соответствие всем условиям платформ.


## Оформление Pakostnik

Добавлена встроенная тема `Pakostnik`: почти чёрные поверхности, белый текст, красные акценты и тёмные сообщения. Она выбирается по умолчанию для новой установки в дневном и ночном режиме. Текст сообщений и экраны Pakostnik используют моноширинный шрифт. Тема доступна также в обычном выборе тем Telegram; существующий выбор темы при обновлении не перезаписывается. Это оформление в запрошенном стиле, без копирования содержимого сайта Doxbin.

## Локальный архив удалённых сообщений

В личной переписке: меню `⋮` → **Удалённые сообщения** — архив только этой переписки.

Главное меню → **Pakostnik AI → Посмотреть удалённые сообщения** — общий архив аккаунта. Если чат выбран внутри Pakostnik AI, кнопка показывает архив выбранного чата.

Клиент сохраняет входящий обычный текст из личных переписок, полученный или загруженный до удаления. После события удаления копия появляется в отдельном локальном архиве. На сервере Telegram сообщение удаляется штатно. По умолчанию локальная запись дополнительно остаётся прямо в переписке с пометкой «✕ удалено»; архив — отдельный способ просмотреть сохранённый текст.

Архив по умолчанию включён, зашифрован ключом Android Keystore и ограничен последними 500 сообщениями не старше семи дней. История архива не отправляется в ИИ. Выключение переключателя хранения, очистка архива или выход из аккаунта удаляют локальные копии. Секретные чаты, защищённые сообщения, текст с таймером удаления и сервисный чат кодов входа не сохраняются. Этот отдельный архив хранит именно текст. Медиа сохраняет механизм удержания сообщений в чате, описанный ниже. Запись в архив может быть пропущена при переполнении очереди или ошибке хранилища.

Сообщения, которых клиент не получил до удаления, восстановить нельзя. Работа события удаления требует проверки на устройстве после первой сборки APK.

## Голосовые и видеокружки

Запись/отправка голосовых и запись/просмотр видеокружков сохраняются из официального Telegram. Используйте штатную кнопку микрофона/камеры в поле сообщения и разрешите доступ к микрофону и камере. Эти функции отдельно на устройстве здесь не проверялись.

Для расшифровки:

1. Откройте переписку с голосовым или кружком и скачайте запись обычным способом.
2. Перейдите в главное меню → **Pakostnik AI → Расшифровать голосовое или кружок**.
3. Выберите запись и подтвердите её передачу вашему серверу и провайдеру распознавания.
4. Результат откроется в отдельном экране с выделяемым текстом. В чат он автоматически не отправляется.

Список содержит до 100 последних полученных или загруженных записей текущего процесса. Секретные, исчезающие и защищённые записи исключены. Размер файла для распознавания — до 24 МБ. Голосовые передаются как OGG, кружки — как MP4; сервер использует `/v1/audio/transcriptions` провайдера OpenAI. HTTPS URL `/transcribe` вычисляется рядом с настроенным `/reply`. Обновите сервер вместе с клиентом; одного старого `/reply` недостаточно.

Модель задаётся переменной сервера `OPENAI_TRANSCRIBE_MODEL`, по умолчанию `gpt-4o-mini-transcribe`. Запросы расшифровки оплачиваются отдельно и вместе с ответами используют общий серверный предел 60 запросов в час. В Caddy или другом reverse proxy разрешите загрузку до 24 МБ и достаточное время обработки. Без ИИ-сервера запись и просмотр медиа работают штатно, расшифровка недоступна.


## Отправка и скачивание медиафайлов

Сохраняется штатный механизм Telegram для фотографий, видео, аудио/музыки, голосовых сообщений, видеокружков, GIF, стикеров и документов. Файлы произвольного расширения можно отправлять как документ: скрепка → **Файл**. Фото и видео можно отправлять из галереи, а для сохранения оригинала — как файл без сжатия.

Скачивание выполняется кнопкой загрузки в сообщении. После загрузки используйте меню сообщения: **Сохранить в загрузки**, **Сохранить в галерею** или **Сохранить в музыку** в зависимости от типа. Документ открывается совместимым приложением Android; отправка файла не означает наличие встроенного просмотрщика для любого формата.

Ограничения размера, доступа к сообщениям и сохранения защищённого контента остаются штатными ограничениями Telegram. Автопилот не блокирует ручную отправку и скачивание медиа; медиа не передаются модели автоответов. Голосовые и кружки отправляются провайдеру только при отдельной расшифровке по вашему действию.

Отправка, загрузка, сохранение файлов и переход к архиву должны пройти проверку на устройстве после первой успешной сборки APK. В рабочей среде проверено наличие соответствующих путей в исходном Telegram и сохранение их после применения изменений; сетевые передачи через реальный аккаунт не выполнялись.


## Сообщения остаются в чате с крестиком

**Включено по умолчанию**: когда приходит удаление ранее полученного входящего сообщения, локальный клиент сохраняет запись и показывает у времени **«✕ удалено»** прямо в обычной переписке. Это действует для обычных входящих сообщений в личных чатах, группах и каналах: текст, фото, видео, голосовые, кружки, музыка, GIF, стикеры и документы. Сервисные события и собственные исходящие сообщения не удерживаются.

Удаление на серверах Telegram не отменяется: другие клиенты увидят его штатно. Клиент фильтрует локальное удаление и сохраняет отметку для повторного открытия чата и следующего запуска. У новых сообщений регистрация выполняется также до передачи обновлений интерфейсу, чтобы обработать быстрое удаление в том же пакете обновлений.

В меню **Pakostnik AI** есть переключатель **«Оставлять удалённые сообщения в чате ✕»**. При его выключении новые удаления обрабатываются обычно. Уже сохранённые записи остаются; их можно удалить самостоятельно. Собственная команда удаления сообщения, очистка истории и выход из аккаунта убирают соответствующие локальные данные и сохранённые файлы.

Скачанные Telegram медиа дополнительно копируются в отдельный каталог внутри хранилища приложения, вне обычного медиакэша. Для удалённой записи приложение пытается открыть сохранённую копию. Копирование выполняется в фоне: при нехватке места, ошибке записи или переполнении очереди файл может не сохраниться. Отдельный лимит размера хранилища пока не реализован. Для новых входящих медиа включено автоскачивание с низким приоритетом; его можно отключить отдельным переключателем в меню Pakostnik AI. Это использует сеть и свободное место устройства. Старые файлы не скачиваются массово при открытии истории. Приложение не обещает получить файл после его удаления с сервера, если его содержимое не было скачано заранее.

Секретные чаты, исчезающие и защищённые сообщения, а также сервисный чат кодов входа не удерживаются. Отдельный текстовый архив по-прежнему ограничен 500 записями/7 днями; это ограничение не применяется к оставленным в переписке записям и копиям медиа.

Переключатель по умолчанию, фильтрация удалений, разделение ID каналов и аккаунтов, сохранение отметок и собственное удаление проверены тестом на изолированных адаптерах. Отображение крестика, работа базы Telegram, воспроизведение всех типов сохранённых медиа и поведение после очистки кэша пока требуют проверки в собранном APK на устройстве.
